# 08. 매일 들어오는 시세와 투자자 거래대금 검증하기

날짜가 없는 투자자 수급 파일을 어느 거래일에 붙일 수 있을까? 같은 파일이 두 번 들어오거나 이미 등록한 값과 충돌하면 어떻게 해야 할까? 시장 거래대금을 먼저 등록하고, 수급 파일의 거래대금과 대조해 거래일을 확정한 뒤 한 번만 반영하는 작은 데이터 저장소다.

원 프로젝트는 DataGuide에서 내려받은 Excel 갱신 파일을 검증해 공용 Parquet 저장소에 증분으로 등록하고, 일별 시세와 투자주체별 거래대금을 등록부로 관리한다. 팀 프로젝트인 [`09_market_data_operations_alba`](../09_market_data_operations_alba)(KRX 크롤러·KIS API를 쓰는 Airflow 수집 파이프라인)와는 **별개의 프로젝트**다. 여기서는 그중 **거래일 대조, 단위 검사, 원본 해시 기록, 재실행과 롤백**을 합성 CSV 3개와 SQLite 트랜잭션으로 재현한다. 모든 종목·금액은 합성값이며 네트워크나 계정이 필요하지 않다.

## 실행

Python 3.10 이상과 표준 라이브러리(`sqlite3` 포함)만 사용하며 외부 패키지는 필요 없다. Windows 11, Python 3.13에서 검증했다. 저장소 루트에서 `code/` 폴더로 이동해 실행한다.

```sh
cd projects/08_market_data_registry/code
python run_demo.py
python -m unittest discover -s tests -v
```

`outputs/`에 SQLite 저장소와 CSV 4개가 생긴다(생성물이라 저장소에는 포함하지 않는다). `python run_demo.py --out demo-run`으로 위치를 지정할 수 있다. 실행할 때마다 해당 이름의 데모 산출물을 같은 합성 입력으로 다시 만든다.

## 세 파일이 한 거래일로 연결되는 과정

1. 가상 3종목의 2월 3일 거래대금 기준본과 2월 4일 증분을 읽는다. 고유 키는 거래일과 종목이다. [기준본](code/data/market_base.csv) · [증분](code/data/market_delta.csv)
2. 날짜가 없는 수급 파일에서 종목별 시장 거래대금(만원)을 원으로 변환한다. 세 종목의 금액이 동시에 일치하는 등록 거래일이 하나여야 한다. 매수·매도·순매수의 단위와 산식도 검사한다. 입력에는 보험·투신·연기금에 해당하는 세 집단만 들어 있다. [수급 입력](code/data/investor_flow.csv)
3. 원본 바이트의 SHA-256과 추가한 행 수를 배치에 기록한다. 같은 키와 값은 건너뛰며, 하나라도 같은 키에서 금액이 다르면 파일 전체를 반려한다. SQLite가 쓰기 트랜잭션을 직렬화한다. [등록·복구 코드](code/market_store.py)
4. 마지막 활성 배치를 되돌리면 그 배치의 행만 사라지고 등록부에 비활성 이력이 남는다. 같은 원본을 다시 등록하면 새 배치 ID와 같은 해시가 남는다. [데모 실행 순서](code/run_demo.py)

`SIM01`의 수급 입력에서 시장 거래대금은 275만원이다. 두 날짜 중 **2025-02-04**의 시장 거래대금 **2,750,000원**과 일치한다. 이날 보험 매수 70만원과 매도 45만원은 순매수 **250,000원**으로 저장된다. 두 날짜의 모든 대조 금액이 같으면 입력을 보류한다.

## 실행 후 확인할 결과

| 파일 | 기본 실행에서 볼 수 있는 값 |
|---|---|
| `run_audit.csv` | 기준본 3행, 시세 증분 3행, 수급 9행 추가. 같은 수급 파일 재입력 때 9행을 중복으로 건너뛴 뒤 롤백·재등록 |
| `registry.csv` | 총 4개 배치. 3번은 롤백 이력, 4번은 동일 해시로 재등록한 수급 배치 |
| `market.csv`, `investor_flow.csv` | 최종 시세 6행과 수급 9행. 각 행의 `batch_id`로 등록 근거를 확인 |
| `sample_store.sqlite` | 같은 등록부와 관측값을 담은 파일. `batches`, `market`, `flows`를 SQL로 조회 가능 |

테스트는 날짜 불일치와 중의성, 단위·순매수 오류, 충돌 시 전체 취소, 프로세스 재연결 후 재입력, 두 작성자의 동시 제출과 롤백 후 복원을 검증한다. 실제 수집기·스케줄러 및 기업특성 계산은 이 코드의 범위 밖이다. [검증 코드](code/tests/test_store.py)

## 파일 구성과 합성/원본 구분

```text
08_market_data_registry/
├── README.md
└── code/
    ├── market_store.py      # SQLite 스키마, 검증, 게시(publish), 롤백
    ├── run_demo.py          # 게시, 재입력, 롤백, 재등록 순서와 CSV 내보내기
    ├── data/                # 합성 입력: market_base.csv, market_delta.csv, investor_flow.csv
    └── tests/test_store.py  # 표준 unittest 8개
```

실제 프로젝트에서 온 것은 위 "원 프로젝트" 문단의 설계 설명뿐이다. 코드와 입력 CSV, 종목(`SIM01`~`SIM03`), 금액은 모두 이 시연용으로 새로 만든 합성 자료이며 실제 시세나 수급 데이터는 포함하지 않는다.
